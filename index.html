Help — what this tool does and does not do

How to use

Drop (or browse) the earlier export as Revision A and the later export as Revision B, then press Compare. Each may be a Primavera P6 .xer or a P6 .xml export. Both files stay on this device; nothing is uploaded.

What the report contains

  • File identity — names, sizes, export dates from ERMHDR, full SHA-256 of each file.
  • Programme shape — activity / link / calendar counts, progress status counts, driving-path note from P6’s own total float.
  • Ranked questions — differences that touched the driving path listed first. Activity ID, name, table and field.
  • Full change register — every material difference, grouped by category, with provenance.
  • DCMA 14-point — separate health snapshot of each revision. Measured value shown so pass/fail is explained. N/A when the file cannot answer.

Driving path rule — and how completed work is handled

The driving path is read as the activities carrying the minimum total float the file itself reports, taken among incomplete work only. Two points make that wording exact, and they are the traps that catch a naive reader:

  • Minimum, not zero. A programme whose required completion sits later than its own network finish carries positive float on every activity. A tool that hunts for float = 0 finds no path at all. What matters is the minimum, whatever its value.
  • Completed activities are excluded on purpose. A finished activity is behind the data date and drives no remaining work, yet the exporters leave a value that would otherwise flag it. Primavera P6 sets a completed activity's total float to null; Microsoft Project writes zero. Read blindly, either would sit at the minimum and put finished work on the driving path. This tool removes completed activities by their status before it looks at float, and it never turns a blank float into zero. A self-test proves this by sabotage: it fails if a completed activity at minimum float is ever allowed onto the path.

Honest limit: this is a descriptive reading of the exporter's own float, not a recomputed critical path. Where a programme mixes several calendars or carries out-of-sequence progress, the exported float can itself be unreliable; a full calendar-aware CPM (ARCHIE) is the right instrument there. Crosscheck tells you what the file says and does not overrule it.

What this tool must never do

  • No CPM recomputation. No half-step. No progress-versus-re-planning split.
  • No entitlement, excusability or compensability language.
  • No expert-report framing. No sealed-custody claims.
  • It records what changed. Establishing who caused it is a forensic analysis and is a separate exercise.

Accepted input

Three programme exports are read, and the format is detected from the file content, not the extension:

  • Primavera P6 XER (.xer) — recognised by its ERMHDR header.
  • Primavera P6 XML (.xml) — recognised by its APIBusinessObjects root.
  • Microsoft Project XML (.xml) — recognised by the Microsoft Project namespace. Summary and rolled-up rows are ignored; only real tasks are read. Microsoft Project reports slack in tenths of a minute, converted here to hours, and a completed task's slack of zero is caught by the completed-activity guard above so finished work is never mislabelled as driving.

Anything that is none of these is rejected with a clear message and nothing is guessed. The XER reader tolerates UTF-8, UTF-16 and common Windows code pages.

Microsoft Project has no stable activity code like P6's. Two MSP revisions are matched on task UID, which is stable when the later file is a saved copy of the earlier one. If the two files were built independently, the change register will show tasks as added and removed rather than edited, and it says so.

Exports — Excel, JSON and Print

After a successful compare, three export buttons become available. All run on this device; nothing is sent anywhere.

Export JSON (verify) — what it is

A small text file (JSON) that records the identity of this comparison batch. It is not the full change list. It is a fingerprint of the two files you compared and a short summary of how many differences were found.

Why you may want it

  • Prove which files were used — the file stores the full SHA-256 of Revision A and Revision B. Months later you can re-hash the same .xer files and show they still match this batch.
  • Keep a light record — email or archive a few kilobytes instead of (or as well as) the full Excel workbook.
  • Handover / audit trail — attach the JSON to a note: “Batch 20260729-HORZ used these two hashes.” Anyone can verify without opening the app.
  • Not a claim document — it does not argue delay, entitlement or cause. It only identifies the inputs and counts.

What is inside

  • Product name, contact email, batch ID, date and time of the compare
  • For each revision: file name, size in bytes, full SHA-256, data date, activity count
  • Summary counts (how many differences, by category, how many questions)
  • A short howToVerify note repeating the hash-check steps

How to open and read it

  • Double-click or open in any text editor (Notepad, TextEdit), VS Code, or a browser — it is plain text.
  • Look for revisionA.sha256 and revisionB.sha256 — those are the fingerprints.
  • Look for batch and comparedAt — so you can match it to the on-screen report and to Excel.

How to verify the hashes (Windows)

In Command Prompt, for each XER file:

certutil -hashfile "HORIZON_RevA.xer" SHA256

Compare the printed value to revisionA.sha256 in the JSON. Repeat for Revision B. Matching values mean the same file bytes were used for that batch.

How to verify (Mac / Linux)

shasum -a 256 HORIZON_RevA.xer (or sha256sum on Linux). Match to the JSON as above.

Filename example: XER_Crosscheck_29-07-2026_Wed_W31_180500_20260729-HORZ_verify.json (UK date, day, week number, time, batch).

Export Excel

A multi-sheet workbook for the full picture: Contents (jump links + both SHA-256 values), Cover, Change register, Questions, DCMA, DCMA lists. Brand bar and support email on each sheet. Use this when you need every line, not only the identity record.

Print

Prints the on-screen report with section codes. Use your browser’s print dialog (Save as PDF if you need a PDF).
